# Skill 只读安装

一期只把 **Skill 说明书** 注入当前这一轮的系统上下文。应用不会执行 Skill 里的代码，也不会按 Skill 发起任意 HTTP 请求。

说明书只进入本轮发给模型的 system 文本，不写进历史消息正文。下一轮不会因为“以前装过”就把全部已安装 Skill 再塞进去。

## 包格式

一个 Skill 由两个文件组成。可以放在 zip 根目录，也可以放在同一个子目录里。

`skill.json` 只允许下面四个字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 显示名，1–80 字。同名再次安装会覆盖说明书，并保留原来的启用开关。 |
| `description` | 否 | 给人看的简介，最长 400 字。 |
| `version` | 否 | 字符串或数字，默认 `1.0.0`。 |
| `triggers` | 否 | 触发词数组，最多 20 个。每个 2–40 字。 |

出现其它字段（例如 `tools`、`http`、`code`、`scripts`）会拒绝安装。

`SKILL.md` 是给模型看的流程说明（Markdown 纯文本）。安装时最长保存 2 万字；真正注入时还会再按本轮预算截断。

内置示例见 `skills/example/`。

```json
{
  "name": "条理化回答",
  "description": "当用户希望分点、按步骤说明时，按固定结构作答。此示例只提供说明书，不含工具。",
  "version": "1.0.0",
  "triggers": ["条理", "分点", "按步骤", "条理化"]
}
```

## 怎样才会被带上

同时满足：

1. 该 Skill 已启用。
2. 本轮用户原文（界面上看到的字，以及工作流实际发送的字）包含任一触发词，**或** 在技能面板里勾了「本轮手动勾选」。

没有触发词的 Skill 只会在手动勾选时注入。匹配按大小写不敏感的子串。

限制：

- 每轮最多 **3** 个。手动勾选优先于触发词命中，其余按安装顺序。
- 本轮注入合计最多 **6000** 字（含固定说明开头），单个说明书最多 **2500** 字，超出部分截断并注明。
- 手动勾选只对下一次成功发出的对话有效，发出后自动取消。刷新页面也会清掉勾选。启用状态会保留。
- 生图请求不注入。
- 点「重答」或「继续」时，只重放这条消息当时带上的、且现在仍启用的 Skill，不会改成“当前全部已安装”。

## 安装与存放

- 顶栏「技能」里可以：安装内置示例、上传 zip、把 `skill.json` 和 `SKILL.md` 粘贴进去、启用 / 禁用、卸载、本轮手动勾选。
- 输入框上方会显示本轮将带上哪些 Skill。发出后，该条用户消息上方也会留下「本轮已带上」。
- 顶栏「预览」的「本轮 Skill」一段，就是将写入 system 的正文。
- 数据写在与对话相同的 IndexedDB（`ZenMuxDB` 的 `settings` 表，键名 `feifan_skills`）。对话快照导入不会清掉这份列表；快照导出目前也不包含 Skill 正文。

zip 只读取名为 `skill.json` 与 `SKILL.md` 的文本，其它文件忽略，不会落地执行。读取 zip 需要页面能加载 JSZip（与现有 Word 解析相同的 CDN）。粘贴安装和内置示例不依赖外网。
